# Post-Phase-3 Candidate Risks

**Basis:** current source/tests and Wave 012/013 validation logs only. Historical discarded audits and secret/provider/env files were not consulted.

## Ranking principles

Risks are ranked by architectural centrality: anything that prevents reliable validation of future architecture waves outranks local UI cleanup; domain correctness contracts outrank test-only corruption; tooling that blocks mandatory build gates outranks peripheral code smells.

## Centrality decision

The most central next improvement is **validation-health architecture with targeted correctness triage**, not another broad source refactor. Future architecture waves currently cannot rely on mandatory validation cadence because known failures are normalized and repeated in implementation logs. A bounded Wave 014 should make the gates green or delete/replace invalid gates, while resolving the intersection contract if it is the true source of the red domain tests.

## Known residual failures explicitly evaluated

- **Full Vitest intersections:** central domain-correctness debt, not mere test cleanup, because implementation and tests disagree on the line-line intersection return contract.
- **Full Vitest PropertiesDialog:** mixed UI contract/test-health debt; important but less central than geometry and gate health.
- **Full Vitest guide-creation:** test-suite health debt; likely collection/placeholder issue unless investigation finds active guide behavior wrong.
- **Node 24/vue-tsc build failure:** validation-tooling debt blocking mandatory build, central to release confidence.
- **Corrupted broad Playwright specs:** e2e-suite ownership debt blocking mandatory user-flow validation; central to future frontend waves, even if not source behavior.
