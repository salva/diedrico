## Remaining-wave centrality / re-rank

No re-ranking edit is required. Wave 003 is still the most central remaining wave because it removes duplicate geometric ownership before persistence and command/undo contract cleanup in Wave 004. Executing Wave 004 first would risk encoding `worldStore` or `ElementTypes` as compatibility surfaces in persistence/serialization decisions. Later rendering/tool/UI waves depend on a single read model from `World`/projection planes.

Recommended remaining order after Wave 003 remains:

1. Wave 004 — command/undo and persistence contract.
2. Wave 005 — process-tree/dependency ownership.
3. Wave 006 — UI command construction into use-cases/tool controllers.
4. Wave 007 — 2D rendering selectors/adapters.
5. Wave 008 — 3D rendering adapters.
6. Wave 009+ as already planned.

## Scope conclusion

Proceed to Wave 003 review convergence. The implementation should delete `Workspace2D.vue`, `ElementRenderer.vue`, `useSnapping.ts`, `useElementGeometry.ts`, and the duplicate geometry-owned `worldStore` surface where evidence proves they are dead. `ElementTypes.ts` should be aggressively deleted if its remaining consumers can be removed or converted to domain/read-model types inside the bounded implementation; otherwise the proposal must define the minimum conversion path needed to avoid retaining a parallel geometry model.
