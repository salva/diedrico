## Contract and structural choice

One confirmation/gesture owns all subordinate model mutations in one Command. Operations run forward, undo in reverse, redo forward. Do not compose independently committed commands to implement one confirmation. Build their operations inside the existing application command boundary instead. No new transaction manager or history-merging heuristic is needed.

`SvgCanvas.handleSaveProperties` previously committed a movement preview, then parameter, then style separately. It now delegates once to `CanvasToolController.updateElementProperties`, reusing parameter operation construction and ordinary Command rollback. This removes UI-side transaction orchestration and avoids misuse of the drag-preview lifecycle for a non-preview dialog. Standalone drag, parameter and style entry points retain their existing contracts.

`PushSubprocessOp` previously undid entry but not creation. Undo now detaches exactly its active empty child through `ProcessTree.undoSubprocessCreation`; children must first have been undone by normal reverse ordering. It never scans/deletes unrelated subprocesses. Redo reattaches the same owned identity; Pop remains navigation only. Descriptor schema unchanged, including old Push descriptors, whose undo now correctly reverses creation.

Did not alter B-owned retention semantics to pretend partial failure is recoverable.
